# Очистка персональной Linux VM

Основа — [вики Cargo C2C](https://wiki.yandex-team.ru/cargo-c2c/docs/tips/how-to-cleanup-vm/), прочитана 2026-09-24. Конкретные команды и уточнения к статье находятся в [references/cleanup.md](references/cleanup.md). Читай нужный раздел перед действием. Это инструкция для целевой VM: создание или установка скилла не означает запуск очистки.

## Определить цель и причину

Используй указанный пользователем SSH-хост или уже установленную сессию. Если хост неизвестен, уточни его; не выполняй Linux-очистку на локальном компьютере вместо VM. Проверь hostname, пользователя, ОС и применимые AGENTS.md. Для shared/prod машины сначала уточни владельца данных и допустимый объём действий: эта инструкция рассчитана на персональную dev VM.

Начни с чтения состояния:

```bash
hostname
id
uname -s
df -h / "$HOME" /tmp /var /place
df -i / "$HOME"
```

Отсутствие `/place` допустимо. Сопоставь каждый кандидат с реальной файловой системой через `findmnt -T <path>`. Смотри свободное место на конкретном физическом разделе: сумма `df --total` и ёмкость Arc FUSE-маунта вводят в заблуждение.

Измеряй ограниченные каталоги: `/tmp`, `/var/log`, `/place/vartmp`, `$HOME/.ya` и точные backing stores Arc. GNU `du -x -h --max-depth=1 <path>` подходит после проверки, что сам путь не является виртуальным маунтом. Проверяй вложенные маунты и исключай их. Не запускай рекурсивные `du`, `find` или индексаторы по корню Arcadia. Не скрывай ошибки доступа так, будто недоступный каталог пуст.

Если `df` показывает существенно больше занятого места, чем `du`, проверь удалённые, но открытые файлы (`lsof +L1`, если доступен). Не завершай процессы автоматически. При исчерпании inode ищи скопления мелких файлов, а не только большие файлы.

## Выбрать действие по измерениям

| Источник расхода | Следующий шаг |
|---|---|
| Кеш ya | Проверить активные сборки, затем `ya gc cache --age-limit=0` |
| Артефакты uservices | Прочитать реализацию `make clean` и её вызываемые команды |
| `/var/log/journal` | Ротация и штатный vacuum journald, при необходимости лимит хранения |
| `/tmp/core-*`, `/tmp/vscode-ssh*` | Выборка старше 3 дней, проверка владельцев и использования |
| `/place/vartmp/preamble-*.pch` | Выборка обычных файлов старше 15 дней |
| Arc object store | `arc gc --dry-run`, затем штатный GC |
| `Transport endpoint is not connected` | Восстановление Arc-маунта из отдельного раздела справочника |

Крупный неизвестный каталог сначала исследуй. Docker, базы данных и системные каталоги не объявляй мусором по размеру; статья не содержит процедуры их очистки.

## Исполнение и границы

Перед удалением покажи короткий конкретный план: пути/фильтры, измеренный размер, последствия и выбранные сроки хранения. Учитывай уже данное разрешение: явный запрос очистить конкретный кеш позволяет выполнить его очистку после диагностики без повторного вопроса. При запросе только на диагностику ограничься планом. Если выбор данных, потеря истории логов, остановка процессов или изменение постоянной конфигурации ещё не согласованы, уточни именно этот пункт после подготовки плана.

Удаляй только проверенные кандидаты в разрешённой области; не подменяй список более широкой маской. Перед удалением перепроверь путь, тип, владельца, возраст и использование. Для каталогов старый mtime родителя не доказывает, что внутри нет свежих или активных файлов. Не следуй симлинкам и не пересекай вложенные маунты. На общей VM чужие файлы не входят в область очистки автоматически.

Не запускай сборки, тесты и их обёртки для проверки очистки без явного запроса. Соблюдай пользовательские и проектные ограничения; никогда не обходи обязательные CI-проверки. Команды из примера вывода `make clean` в вики не являются самостоятельным списком для запуска.

Выполняй выбранные операции по одной и измеряй результат на том же физическом разделе. При неожиданном составе файлов, изменении состояния Arc или несоответствии хоста останови затронутую операцию и объясни расхождение. Если места уже достаточно для цели пользователя, не переходи автоматически ко всем остальным способам и не повторяй GC без нового основания.

Не удаляй `~/.arc`, object store, overlay или RocksDB вручную в рамках обычной очистки. Пересоздание Arc-хранилища — отдельная задача восстановления с сохранением локальной истории, стэшей, отслеживаемых и неотслеживаемых файлов. Токены не выводи в чат или логи.

## Проверить результат

Повтори `df` на исходных разделах и размеры очищенных каталогов; для journald — `journalctl --disk-usage`, для Arc — статус и проверку сохранности изменений. Удаление открытого файла может не освободить место до закрытия дескриптора; выясни причину, не расширяй удаление вслепую.

Сообщи хост, свободное место до/после и фактические действия. Отделяй оценку размера кандидатов от реально освобождённого места. Укажи оставшиеся причины расхода и ошибки; не заявляй, что они вызваны очисткой, без доказательств.
