# Скриптовый scheduler (macOS)

Пути с `~` разрешай относительно домашнего каталога; в JSON-параметры инструментов
передавай раскрытые абсолютные пути. Runtime и скиллы разворачивает профиль Dotter `ai`.

Установленный runtime: `~/.local/share/arcanum-pr-poller/poller.py`.
Конфигурация: `~/.local/share/arcanum-pr-poller/config.json`.
LaunchAgent: `com.lorut0.arcanum-pr-poller`, файл в `~/Library/LaunchAgents/`.
Исходник и тесты: `~/.config/dotfiles/scripts/arcanum-pr-poller/`.
Это общая установленная зависимость двух скиллов; при переносе сначала установи
runtime и LaunchAgent, проверь пути. Не подменяй отсутствующий runtime heartbeat.

launchd запускает `poller.py tick` каждую минуту; скрипт опрашивает только PR, для
которых истёк индивидуальный интервал (10 минут в этом режиме). Между событиями
модель не вызывается. Нужны пользовательская сессия macOS, работающий локальный
Codex app-server, сеть/VPN и штатная авторизация Arcanum. После сна пропущенные
интервалы не воспроизводятся пачкой: проверяется последнее состояние.

## Регистрация после первого ревью

Сначала проверь `status` и конфигурацию: один PR может иметь только одного владельца.
Определи точный ID текущего чата; не выбирай произвольный чат. Сохрани state ревью
с observed head/base/merge, comments (id, text_sha256/content_sha256, status/issue_status)
и checks (полные items). Для существующих state поддержаны схемы обоих скиллов.
Первый скриптовый опрос сравнивает remote с этим state; при несовпадении ставит событие,
при совпадении создаёт baseline без вызова модели. Несовместимый state — явная ошибка,
не повод молча считать новый snapshot проверенным.

```sh
python3 ~/.local/share/arcanum-pr-poller/poller.py register \
  --pr <PR_ID> --thread <EXISTING_CHAT_UUID> \
  --skill ~/.codex/skills/arcanum-auto-review/SKILL.md \
  --review-state <ABSOLUTE_STATE_JSON> --interval 600
```

Уточняй синтаксис через `--help`; перед исполнением замени все placeholders.
Успех register означает регистрацию, а не доказательство работающего launchd.
Проверь `launchctl print gui/<uid>/com.lorut0.arcanum-pr-poller` и `check --dry-run`.
Не запускай `check` без dry-run ради проверки: при изменениях он вызовет модель.

## Диагностика и остановка

- `poller.py status` показывает интервалы, last_checked, ошибки и inflight event.
- `poller.py check --pr <ID> --dry-run` читает PR и показывает, нужна ли доставка,
  не отправляя сообщение модели и не меняя baseline.
- `poller.py stop --pr <ID>` прекращает опрос этого PR. Другие мониторы продолжают работать.
- `poller.py resume --pr <ID>` возобновляет только по прямой просьбе пользователя;
  baseline сохраняется, поэтому учитываются изменения за время остановки.
- Лог launchd: `~/.local/share/arcanum-pr-poller/launchd.log`.

Сбой API/авторизации сохраняется как локальная ошибка и повторяется на следующем
опросе без модели. Скрипт не читает код и не выполняет ревью, не пишет в Arcanum.
Он сравнивает ревизию, description/summary/status/approvers, все comments/replies и
checks/run IDs. Изменения внешнего Tracker без изменения PR не являются триггером;
при следующем событии агент заново читает требования.

## Доставка и ack

`codex queue --thread … --message …` получает аргументы массивом без shell и без
смены модели/прав чата. До отправки создаётся устойчивый inflight event. Пока агент
не выполнил `ack`, скрипт не опрашивает этот PR и не ставит второй проход. После ack
следующий опрос прочитает последнее состояние, включая изменения за время ревью.
После ack baseline обновляется строго снимком этого события; изменения, появившиеся
за время анализа, остаются для следующего запуска.

При неизвестном исходе отправки скрипт не повторяет её автоматически. Проверь чат
по event ID; если агент обработал событие, подтверди его штатным ack. Если доставка
достоверно отсутствует, восстанови её вручную после проверки — не стирай журнал
наугад. Исход `blocked` освобождает доставку без повторных вызовов на том же PR state.
Старые heartbeat должны оставаться PAUSED: их включение вернёт пустые модельные вызовы.

## Компактный опрос и ограничения нагрузки

Обычный неизменившийся PR: два GET (если списки не требуют дополнительных страниц).
1. `/api/v1/review-requests/<PR>?fields=...` — id, updated_at, state/full_status,
   active_diff_set с commit IDs, approvers и версии/status/IDs checks.
2. `/api/v2/public/pull-request/<PR>/comment?fields=...` — id, reply_to_id, draft,
   updated_at/thread_updated_at, issue_status/deleted_at и версии реакций. Текстов нет.

Компактный fingerprint сравнивается отдельно от baseline полного snapshot. Если
маркеры прежние, полные ручки не вызываются и модель не запускается. При изменении
загружается полный snapshot и только его содержательное отличие создаёт событие.
Раз в 6 часов выполняется контрольная полная сверка без обязательного вызова модели;
она страхует от неполного покрытия timestamp-полями. При первой миграции нужен один
полный снимок для привязки новых маркеров к сохранённому baseline.

Нельзя заменить это одним PR.updated_at: на проверенном PR timestamp проверки CI
новее timestamp PR. Одинаковое число комментариев также не исключает правку текста,
смену статуса issue, удаление/замену ответа. ETag/Last-Modified проверенные ответы
не предоставляли; cache-control запрещал кеширование.

В общей config.json параметры: minimum_request_gap_seconds=2,
max_requests_per_hour=120, max_requests_per_pass=16, jitter_seconds=30,
reconcile_seconds=21600. Это выбранные локальные ограничения, **не квота Arcanum**.
http-budget.json + http.lock делят бюджет между всеми PR и параллельными процессами.
Ручной check, включая dry-run, подчиняется тому же бюджету и backoff.

429/503: учитывать Retry-After (секунды или HTTP-date), общий cooldown; после
повторных ошибок задержка возрастает. 401/403: минимум час до следующей попытки.
Таймер не делает быстрых ретраев, baseline при ошибке остаётся прежним, модель не
вызывается. Неполный компактный ответ не заменяется скрытым тяжёлым опросом.
В launchd.log поле http_requests показывает реальное число HTTP-попыток прохода.

Контракты проверены по https://arcanum.yandex.net/api/swagger.json и
https://arcanum.yandex.net/api/public-swagger.json, а также read-only запросами.
Точечное projection уменьшает ответ и число HTTP-вызовов; стоимость backend/БД
не измерялась. При наличии тысяч комментариев даже компактный список растёт;
для такого масштаба отдельно рассматривай документированную Xiva-подписку.
